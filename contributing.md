# Contribution Guidelines

Please note that this project is released with a [Contributor Code of Conduct](code-of-conduct.md). By participating in this project you agree to abide by its terms.

## Criteria for Awesome Computer Use

To be considered for inclusion, an item must meet the following criteria:

- **Relevance**: Directly related to computer use, GUI agents, multimodal visual grounding, OS automation, or computer use benchmarks.
- **Quality**: Actively maintained, documented, reproducible, and open-source or publicly accessible.
- **Originality**: Duplicates or shallow wrappers without substantial engineering additions will not be accepted.
- **No deprecated projects**: Archived or unmaintained repositories will be removed.

## Formatting Standards

When proposing additions:

1. **Title Casing**: Project names must use standard project capitalization.
2. **Alphabetical Order**: Insert new items in alphabetical order within the most appropriate section.
3. **Description Format**:
   - Must begin with a capitalized character.
   - Must be objective, factual, and concise (not marketing copy or hype).
   - Must end with a period.
   - Format: `- [Project Name](https://example.com) - Concise description of capabilities.`
4. **Link Format**: Use permanent, clean HTTPS links (prefer GitHub repository roots or official project sites).

## Pull Request Process

1. Fork this repository.
2. Create a feature branch with a descriptive name (`git checkout -b add-my-project`).
3. Make your additions adhering strictly to the formatting standards above.
4. Verify alphabetical sorting.
5. Submit a pull request explaining why the project is awesome and why it belongs in the list.
